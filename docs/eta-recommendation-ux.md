# ETA 추천 고도화 — 메뉴별 준비시간과 사용자용 추천 문구

화면 코드 수정 없이 도메인 계층만 변경했다. 메뉴·주문 확인 화면은 기존처럼 `recommendation.label`과 `reason`을 표시하므로 변경 내용이 그대로 나타난다.

## 1. 준비시간 추정 (`PreparationEstimate`)

준비시간 = 매장 기본 준비시간 + 메뉴 추가시간 + 수량 추가시간 (최대 120분)

| 요소 | 규칙 | 근거 |
|---|---|---|
| 매장 기본 | `Store.preparationMinutes` (A 6분, B 5분) | 기존 값 유지 |
| 메뉴 추가 | 담은 메뉴 중 가장 큰 `MenuItem.extraPreparationMinutes`만 더함 | 여러 음료는 병행 제조한다고 가정 |
| 수량 추가 | 첫 잔 이후 2잔마다 +1분 (`(총 잔 수 − 1) / 2`) | 잔 수가 늘면 조금씩 늦어짐 |

메뉴 추가시간(데모 추정값): 아메리카노 0분, 카페라떼 1분, 바닐라라떼 2분, 콜드브루 0분.

- 장바구니가 비어 있으면 매장 기본값을 쓴다.
- 데모 설정의 '매장 준비시간 덮어쓰기'를 켜면 그 값이 추정 전체를 대체한다. 기존 시연 조합(ETA 10 · 준비 5 → 약 4분 후)은 그대로 재현된다.
- 아메리카노 1잔 + 매장 A는 6분이므로 기존 시연 기준(ETA 8 · 준비 6 · 여유 1 → 약 1분 후)도 바뀌지 않는다.
- 모든 값은 실제 매장 POS 데이터가 아닌 추정값이다.

## 2. 추천 문구 (`OrderTimingCalculator`)

계산식(대기 = ETA − (준비 + 여유 + 지연))과 판정(지금 / 약 N분 후 / 도착 후)은 변경하지 않았다. 설명 문구만 계산식 나열에서 결과 중심으로 바꾸고, `arrivalGapMinutes`(도착 시각 − 준비 완료 시각)를 추가했다.

| 상황 | 예시 문구 |
|---|---|
| N분 후 주문 | 도착 약 8분 · 준비 약 6분. 약 1분 후 주문하면 도착 약 1분 전에 준비됩니다. 추정값입니다. |
| 지금 주문, 도착 전 준비 | 도착 약 8분 · 준비 약 7분. 지금 주문하면 도착 약 1분 전에 준비됩니다. 정차 중에만 주문하세요. |
| 지금 주문, 도착과 동시 | … 지금 주문하면 도착과 거의 동시에 준비됩니다. … |
| 지금 주문, 도착 후 대기 | 도착 약 3분 · 준비 약 6분. 지금 주문해도 도착 후 약 3분 기다릴 수 있습니다. … |
| 지연 설정 | N분 후: "(지연 2분 대비 포함)", 지금: "(매장 지연 시 최대 2분 더 걸릴 수 있음)" |
| 도착 후 주문 | 기존 문구 유지, `arrivalGapMinutes = null` |
