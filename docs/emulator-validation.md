# 에뮬레이터 검증 기록

검증일: 2026-10-29. Pleos Connect v2.1.0 / API 34, emulator-5554.

## 확인된 결과

- ADB 장치 연결 및 `com.example.pleoshellocar/androidx.car.app.activity.CarAppActivity` Resumed 상태 재확인.
- 이전 직접 화면 검증: 홈 → 매장 A → 메뉴 수량 선택 → 확인 → 모의 결제 → 주문번호 → 내 주문 → 준비 중 → 픽업 준비 완료.
- Mock DRIVING 상태의 매장 선택 차단 확인. UNKNOWN/PARKED/DRIVING의 도메인 조작 정책은 단위 테스트로 검증.
- 모의 결제 실패 후 재시도 성공 화면 확인.
- shared 도메인 테스트 20개, automotive 기본 테스트 1개, mobile 기본 테스트 1개: 총 22개 통과. 기본 테스트 2개는 실제 사용자 흐름 검증을 대체하지 않는다.
- automotive/mobile assembleDebug 및 각 모듈 testDebugUnitTest 성공. Gradle 10 관련 사용 중단 경고 존재.

## ETA 결과 정정

기본 안전 여유 1분, 최소 처리시간 1분 기준이다.

| ETA | 준비 | 지연 | 결과 |
|---|---|---|---|
| 8 | 6 | 0 | LATER, 1분 후 |
| 10 | 5 | 0 | LATER, 4분 후 |
| 3 | 5 | 0 | NOW, 도착 후 대기 가능 |
| 8 | 6 | 2 | NOW |
| 0 또는 1 | 5 | 0 | AFTER_ARRIVAL |
| 없음/음수/181 이상 | 5 | 0 | AFTER_ARRIVAL |

이전 문서의 ETA 3분에 대한 AFTER_ARRIVAL 표기는 오류였다. DemoSettings는 입력값을 변경하며 추천 결과는 메뉴·확인 화면에서 다시 계산한다. 실제 이동에 따른 자동 ETA 갱신은 구현하지 않았다.

## 안전 정책 및 템플릿

`ParkedOnlyOnClickListener`는 호스트의 정차 판단으로 클릭 실행을 제한한다. Mock 상태 검사와는 별개다. `InteractionPolicy`는 주문 변경·확정·취소·진행을 PARKED일 때만 허용한다. Mock DRIVING/UNKNOWN이 모든 설정 버튼을 비활성화한다는 이전 설명은 부정확하다. 호스트가 정차 상태이면 데모 설정을 변경할 수 있다.

현재 행 수: 홈 3, 매장 4, 메뉴 6, 상태 5, 설정 5. 확인 Pane은 4행·액션 2개다. List 6행/Pane 5행 검사는 앱 자체 상한이며 보편적인 SDK 한도나 심사 통과 보장이 아니다. 호스트별 content limit, 템플릿 할당량과 지원 카테고리를 별도로 검증해야 한다.

완료 화면에서 긴 메시지가 잘리는 현상을 확인했다. 본문을 주문번호와 필수 모의 결제 안내의 두 줄로 줄였다. 2026-10-29 병합된 main APK 재설치 후 완료 화면의 두 줄(주문번호·실제 청구 없음)이 잘림 없이 표시됨을 직접 확인했다. 결제 실패→재시도 성공, 준비 중→픽업 준비 완료→취소 화면도 재확인했다.

## 남은 한계

실제 차량·내비게이션·매장·결제 서비스 연동 없음. 상태는 세션 메모리이며 세션 재생성 시 초기화된다. 상태 전환은 버튼 기반 시뮬레이션이다. 음성 대신 텍스트 알림을 표시한다. 전체 예외 시나리오를 에뮬레이터에서 재실행한 것으로 주장하지 않는다.
