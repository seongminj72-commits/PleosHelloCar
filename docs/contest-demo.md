# 3~5분 공모전 데모 시나리오

## 준비

Pleos Connect v2.1.0 API34 AVD를 실행한다. 호스트 차량 상태를 실제 정차로 설정한다. 앱을 새로 실행하면 Mock 차량 상태는 UNKNOWN이다. 모든 매장·ETA·결제·주문 상태는 시뮬레이션임을 먼저 설명한다.

## 진행 (약 4분)

1. 0:00~0:40 홈: 차량 ETA와 준비시간을 연결해 주문 시점을 제안하는 가치를 설명한다. 서비스 상태에서 Mock PARKED로 전환한다.
2. 0:40~1:30 매장 A 선택. 아메리카노를 탭해 1개 선택. ETA8/준비6/여유1이면 약 1분 후 주문 추천임을 보여준다. 자동 주문이나 확정 도착 약속이 아님을 설명한다.
3. 1:30~2:10 홈으로 돌아가 데모 설정에서 DRIVING으로 전환한다. 매장 선택 시 제한 안내를 보여준다. 다시 UNKNOWN을 거쳐 PARKED로 전환한다. Mock 설정은 실제 차량 안전 신호가 아님을 설명한다.
4. 2:10~3:10 매장·메뉴 재선택 → 주문 확인 → 모의 결제 승인. 실제 금액 청구가 없다는 안내와 주문번호를 확인한다.
5. 3:10~4:00 홈 → 내 주문. 진행 버튼으로 준비 중 → 픽업 준비 완료 → 완료를 보여준다. 실제 매장 이벤트가 아닌 수동 시뮬레이션이며 알림은 텍스트임을 설명한다.

## 선택 장면

ETA10/준비5에서 약 4분 후, ETA3에서 지금 주문 추천으로 변경한다. 실패 시뮬레이션을 켜 결제 실패와 동일 주문 재시도를 보여준다. 시연 전 해당 조합을 직접 연습한다.

장바구니에 따른 추천 변화(준비시간 덮어쓰기는 '매장 기본값 사용', ETA 8분): 아메리카노 1잔이면 "약 1분 후 주문하면 도착 약 1분 전에 준비됩니다", 아메리카노를 3잔으로 늘리면 준비 약 7분으로 바뀌어 "지금 주문하면 도착 약 1분 전에 준비됩니다", 아메리카노 1잔 + 바닐라라떼 1잔이면 준비 약 8분으로 "도착과 거의 동시에 준비됩니다"가 표시된다. ETA3에서는 "지금 주문해도 도착 후 약 3분 기다릴 수 있습니다"로 도착 후 대기를 숫자로 보여준다. 메뉴 추가시간과 수량 반영 규칙은 [추천 고도화](eta-recommendation-ux.md)를 참고한다.

## 제출 전 남은 검증

수정된 완료 화면의 두 줄 가독성, 모든 예외 흐름, 호스트별 템플릿 제약, POI 카테고리의 주문 데모 허용 범위를 확인한다. 실제 SDK·실차·실제 결제 연동은 시연 완료로 표현하지 않는다. PG 연동은 이번 MVP의 필수 산출물이 아니다.
