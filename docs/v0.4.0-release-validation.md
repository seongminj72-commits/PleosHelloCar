### 비교 시험: v0.3.1 기준선 (2026-11-11 14:23 KST, Claude 분석)

Codex 작업이 중단되어 사용자 Mac에서 스크립트로 시험하고, 녹화를 Claude가 프레임 단위로 분석했다. 조건은 Pleos_Connect_v2.1.0, 콘솔 P·0이다. 회차마다 `adb uninstall` → `adb install` → HOME → `logcat -c` → `screenrecord` 시작 1.5초 후 `am start --user current -n …/CarAppActivity`로 실행했다. 녹화는 2560×1440, 약 52fps, 7초다.

- 사용 APK SHA-256: v0.3.1 `b2537264…dd13453`(v0.3.1 태그의 제출 APK), v0.4.0 `f0faf2af…448496a`(커밋된 제출 APK)
- 판정 방법: 실행 직후 1.6초 구간을 25fps로 잘라, 오류 문구가 나타나는 영역(앱 창 오른쪽 중앙)을 시간순으로 나열해 육안으로 확인했다. 시험 중 런처 앱 서랍이 문구 왼쪽 부분을 가려 "…ted error" 꼬리만 보인다.

로그 확인:
- 6회 모두 앱 쪽 `CarApp.Act`는 템플릿 호스트(`com.android.car.templates.host`)에 바인딩되고 핸드셰이크에 성공했다. `CarApp.Act` 오류 로그, `RemoteException`·`DeadObjectException`·`FATAL`은 없었다.
- Car App Library 1.7.0의 `CarAppActivity` 자체 오류 화면은 `ServiceDispatcher`가 예외를 잡을 때만 `ERROR` 상태로 표시된다. 그 경우 반드시 `CarApp.Act` 태그의 `Log.e`가 남는데(androidx 소스 `ServiceDispatcher.fetch`), 이번 로그에는 없었다.
- 라이브러리의 오류 문구는 "Unknown error", "System error" 등이다. 화면의 "has encountered an unexpected error"는 라이브러리 문구가 아니므로, Pleos 템플릿 호스트가 렌더링한 화면으로 판단한다.

판정:
- **v0.3.1 제출 APK에서도 같은 문구가 같은 시점에 재현되므로 v0.4.0에서 생긴 회귀가 아니다.** 첫 템플릿이 표시되기 직전, 호스트 전환 중에 약 0.2초 보이는 현상이다.
- 빈도는 v0.3.1 1/3, v0.4.0 3/3으로 차이가 있다. 다만 v0.3.1의 나머지 2회에도 같은 시점에 회색 전환 띠가 보여, 같은 화면이 더 짧게 지나갔을 가능성이 있다. 3회 표본으로는 빈도 차이를 확정할 수 없다.
- 앱 기능에는 영향이 없다(같은 실행에서 홈이 정상 표시되고 조작 가능).
- 남은 위험: 심사위원이 첫 실행 때 순간적으로 오류 문구를 볼 수 있다. 시연 영상에서는 해당 프레임을 제외한다. 호스트 쪽 원인이라 앱에서 확실히 없앨 방법은 확인하지 못했다.
- 미실행: 콜드 부팅 직후 시험, 런처 아이콘 탭 실행 비교. 원본 녹화와 로그는 사용자 Mac의 `~/driveflow-firstlaunch/`에 있다.
